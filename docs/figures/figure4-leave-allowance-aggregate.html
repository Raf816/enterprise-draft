Denormalised staff data: managerId, firstName, surname and department are synced from Staff Management via remote events (StaffMemberAddedEvent, StaffMemberUpdatedEvent). Staff Management remains the authoritative owner.
No direct link to LeaveRequest. Changes affecting both aggregates are coordinated through domain events, not direct object references. Neither aggregate controls the other.
Available Days = Total Entitlement − Days Used − Days Pending
Calculated at access time, not stored. This prevents inconsistent balance values.

BusinessYear represents one fiscal year (e.g. 2026–2027). Start and end must be consecutive years. A composite unique constraint (staffMemberId, businessYear.startYear) ensures one allowance per staff member per year.
Balance Operations (triggered by domain events):
reserveDays(n) daysPending += n ← LeaveRequestSubmittedEvent
confirmDays(n) daysPending −= n, daysUsed += n ← LeaveRequestApprovedEvent
releasePendingDays(n) daysPending −= n ← LeaveRequestRejectedEvent / CancelledEvent (pending)
creditBackDays(n) daysUsed −= n ← LeaveRequestCancelledEvent (approved)
amendEntitlement(n) totalEntitlement = n ← Admin action via PATCH endpoint
Relationships:
LeaveAllowance ◆ BusinessYear — composition (value object defining the fiscal period)
