Identity and Access Control (Generic Context) Uses a simpler structure (AuthController → FirebaseAuthService → SecurityConfig) because it handles authentication, identity and roles without requiring domain-oriented modelling. DDD layering is applied selectively according to each context's responsibility and complexity.
Common (Shared Kernel) Kept deliberately small. Shared domain concepts (Identity, Email, FullName) provide consistent meaning across contexts. Shared event contracts and infrastructure (RemoteEvent, LocalEvent, DomainEventManager, EventStore) support cross-context messaging without coupling context-specific behaviour.
▲ Dependency direction: each layer depends only on the layers below it. Domain depends on nothing.
Infrastructure mirrors Domain via the Data Mapper pattern but Domain does not import Infrastructure.
